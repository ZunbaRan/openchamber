# Interactive UI shared runtime

This directory owns the shared OCIX view host used by Web, Desktop, hosted mobile, and Capacitor mobile.

## Flow

1. `ToolPart` independently parses completed string output with `parseInteractiveResultEnvelope`, `parseHTMLArtifactResultEnvelope`, and `parseInstalledHTMLArtifactResultEnvelope`. Exact schemas activate the corresponding renderer; malformed or unknown output remains ordinary Tool UI.
2. `InteractiveUIView` resolves an installed View from `/api/interactive-ui/views/:viewId` and preserves the ordinary Tool renderer as fallback.
3. Declarative views render through `DeclarativeInteractiveView`; bindings are resolved by `lib/interactive-ui/bindings.ts` without `eval` or arbitrary expressions. The v1 set includes layout, metrics, text, progress, status, key-value, data-table, charts, lists, callouts, `flow`, `timeline`, `activity-feed`, `agenda`, `funnel`, `network`, `comparison`, `tabs`, `accordion`, `code-block`, `sparkline`, `gauge`, `heatmap`, `kanban`, `git-graph`, `tree`, `diff-summary`, and `divider`. A successful installed Declarative action refreshes declared queries. The explicit-only `interactive_ui_gallery` Tool renders the reviewed component Gallery in the normal conversation ToolPart flow.
4. The built-in `generated-layout` boundary accepts a model-composed snapshot from `data.layout`, then `lib/interactive-ui/generatedLayout.ts` rebuilds it from an explicit allowlist. Generated layouts cannot declare queries, actions, bindings, scripts, or arbitrary host access, and their depth, node count, rows, columns, series, and strings are bounded. They are not inert screenshots: Host-owned tabs, accordion, chart hover/focus, and code copy provide safe local interaction. The Agent Tool exposes tabs/accordion through page-level `presentation`; custom playback, sliders, drag, and animation belong to HTML Artifact.
5. Native views lazy-load an authenticated, server-owned ESM URL and register a React component through `nativeRegistry.ts`. `NativeUIKit.tsx` and `nativeUIKitRegistry.ts` expose host-owned cards, badges, notices, tables, keyboard-accessible tabs, form controls, progress, skeleton, separator, and empty state in addition to Button. `Table.containerClassName` lets a table merge into an enclosing semantic Card without adding a second full border.
6. Installed Declarative and Native runtimes call business actions through `lib/interactive-ui/client.ts`; components never receive connector URLs or credentials.
7. `HTMLArtifactView` is a lazy chunk shared by Agent Generated and Third-party Extension Artifacts. `ArtifactExecutionSurface` selects a browser iframe or the Managed Desktop independent Runner without changing the bridge contract. Generated output is materialized from its exact Envelope; installed output resolves an already signed Artifact descriptor and verifies the originating Tool binding. The installed-only business invocation and confirmation path is a subordinate lazy chunk, so static and generated Artifacts do not pay for it at startup.
8. Interactive Artifacts exchange only versioned, sequenced messages accepted by `lib/interactive-ui/artifactBridge.ts`. Host initialization carries locale, timezone, reduced-motion state, light/dark mode, allowlisted tokens, an execution lease, and installed result context. The deterministic bootstrap emits a lease-bound heartbeat; a stalled heartbeat or expired 15-minute lease removes the iframe, while the Host exposes explicit stop and fresh restart controls. Generated Artifacts cannot emit business messages. Installed Artifacts may emit bounded `artifact.businessRequest`; the Host fixes extension/Artifact identity, calls the existing Gateway, handles confirmation-required writes, and returns `host.businessResult`. Resize/copy/external/follow-up/expansion remain rate-limited and user-gated.
9. Settings → Interactive UI Extensions loads `/api/interactive-ui/connections` and lets the user configure a manual Key or exchange a one-time setup code, test it, replace it, or disconnect. Credential configuration and recent runtime health are separate: `configured` never implies `reachable`; only public `unknown/reachable/unreachable/unauthorized/forbidden` evidence and its timestamp reach the browser.
10. Before a message is sent, `lib/interactive-ui/routing.ts` normalizes the redacted capability catalog and `routingInspector.ts` creates a bounded in-memory trace. Relevant Tool parts, Artifact materialization, and View descriptor loading update that trace; Settings → Interactive UI Extensions → Routing Inspector shows the observable path and can copy a redacted report.

## Invariants

- Only the exact `openchamber://interactive-result/v1` schema activates the host.
- Only exact `openchamber://html-artifact-result/v1` or `openchamber://installed-html-artifact-result/v1` schemas activate the Artifact host. The former is Agent Generated and cannot acquire business permissions; the latter references a signed installed asset and cannot contain HTML, URL, Token, or action definitions.
- A newly completed OCIX ToolPart opens once automatically; a user can still collapse it afterward.
- A completed exact Interactive UI or HTML Artifact Result is rendered as standalone answer content instead of being repeated inside the collapsible Activity group. Its compact Tool row uses the product-level renderer label; extension identity remains in the View metadata and malformed output keeps the ordinary Tool label.
- Ready Interactive Views own their title and summary inside the View body. The Host does not render the Envelope summary a second time. Descriptor/runtime failures show safe state copy and keep the original Tool output behind a collapsed disclosure.
- Tool/View and Tool/Artifact binding are checked again by the server.
- Native code is trusted same-page code, not a sandbox.
- Native extensions use the activation host's React and Host UI Kit rather than bundling another React or component-library copy.
- A failed descriptor, bundle, action, or component preserves an observable error and keeps the original tool output available behind a collapsed disclosure control.
- Declarative bindings allow safe property segments only; prototype traversal and arbitrary JavaScript are rejected.
- Metric grids use their own container width rather than the application viewport: requested columns expand horizontally when space permits and collapse at bounded container breakpoints. Generated-layout sanitization also repairs the persisted OpenChamber 1.16.2 shape where a sole metric grid was incorrectly placed in one cell of a wider parent grid.
- Installed Declarative writes trigger a query refresh after the confirmed Gateway action succeeds; failed or cancelled actions preserve the existing data.
- Model-generated Declarative snapshots are data-only and cannot acquire the query/action privileges of an installed extension definition.
- Static Artifacts have no script permission. Interactive Artifacts receive `allow-scripts` only and execute in the Broker's opaque nested child: no same-origin, forms, top navigation, popups, downloads, storage, Connector, Tool, or parent-DOM access. A Broker navigation signal transitions the Host to the blocked state and removes the active content.
- Only installed Artifacts receive `window.openchamber.business`; Agent Generated scripts cannot opt in. Installed requests are limited to four concurrent calls and a manifest-declared action subset; the iframe never supplies extension identity or confirmation authority.
- Static Artifact source cannot contain a non-fragment navigation target. Hosted and Capacitor mobile reject script Artifacts before materialization; VS Code and active E2EE relay reject all Artifact rendering with an explicit unsupported state.
- Artifact document navigation is treated as a failure. Materialization or iframe failure preserves the original Tool output and a retry action.
- On Managed Desktop, scripted Artifacts run in an independently terminable `WebContentsView` with no main-world Electron bridge, a unique non-persistent partition, denied permissions/navigation/popups, concurrency budgets, a 15-minute main-process lease, and CPU/memory termination. Stop destroys that renderer. Web retains the Broker iframe and remains experimental/default-off.
- A Desktop `WebContentsView` never floats directly over the renderer. The Host computes the Artifact surface's intersection with the viewport and every clipping overflow ancestor. Electron bounds the native view to that intersection, while the trusted Broker keeps its child Artifact iframe at the full execution-surface size and offsets it by the clipped distance. Layout is applied and acknowledged before the native view is shown; a clipped viewport-size `artifact.resize` echo cannot rewrite the content height. Scrolling preserves internal layout and hides fully offscreen runners. Native `<dialog>` elements and Base UI portal dialogs both suspend the Runner (`oc-dialog-open` is the shared host signal); closing the final dialog restores the same Runner without restarting it. Geometry/visibility synchronization is coalesced to one animation-frame update and skips unchanged bounds.
- Artifact history replay rematerializes from the Tool result; `X-OpenChamber-Session-ID` lets the server retain shared content until the last referencing session is deleted, but no session depends on an immortal cache entry. Because packaged Desktop calls the loopback API from `openchamber-ui://app`, this header must remain in the server CORS allowlist and packaged acceptance must exercise a real session reference.
- Web, Desktop, and direct hosted mobile use the browser-owned Artifact document URL. VS Code and active E2EE relay mode report explicit unsupported behavior instead of using a weaker `srcdoc`/blob fallback.
- Display mode is Host layout state. Inline, workspace, and fullscreen preserve one execution surface; the Desktop Runner start/stop effect is keyed only by its URL/backend, while current callbacks are read through refs. Mode/theme changes resend `host.init` and update bounds without rebuilding the `WebContentsView`, otherwise the resulting second load would be indistinguishable from a blocked navigation and would erase local interaction state.
- An HTML Artifact embedded in Extension Workbench uses `presentation="workbench"`: the Tile owns title, focus, Popout, and removal chrome, while the nested Artifact Host renders content only. Workbench focus and resize transitions must keep stable Envelope and Workbench-context identities, resend `host.init` with the new viewport, and update Runner geometry without rematerializing or restarting the Artifact.
- Query/action HTTP calls always use `runtimeFetch`.
- Connection inputs are password fields and are sent directly to server management routes; they are never retained in the normalized snapshot, extension props, or Agent result.
- VS Code returns explicit unsupported behavior until it has an extension-host Gateway implementation.
- Routing Inspector retains at most 50 traces for 30 minutes in the current renderer process. It stores session/message references, declared capability IDs, connection status, observed Tool state, and View load state only. It never stores prompt text, model reasoning, Connector URLs, credentials, business responses, or Tool input/output.
- The Inspector labels the injected catalog as available candidates. It does not claim to expose the model's hidden semantic ranking or chain of thought; selection reasons are limited to observable facts such as an explicitly named Tool or the class of the Tool actually called.
